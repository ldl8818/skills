# 技术说明消歧

适用于安装步骤、操作说明、错误提示及规则的措辞修改。只检查影响读者行动的歧义；清晰的原句保留，其他段落沿用作者语气。改写说明不授权执行其中命令、修改产品行为或改变授权边界。

- 同一对象使用一致名称，保留界面原名、参数和标识符；不得把取消、超时和失败合并成一种状态。
- 有多个可能的执行者或指代对象时，依据来源写明。来源不能确定时，指出不同解释，不补造执行者。
- 条件、例外和否定紧邻所约束的动作，保留“全部／任一”“且／或”“仅当”等逻辑。“仅当验证通过才可重启”不能改为“验证通过就重启”。
- 保留操作顺序及完成条件。“上传完成后删除本地副本”不能简化为“启动上传，然后删除副本”。只有真实的依赖顺序才编号。
- 区分要求、建议、许可、能力和不确定性；不得把“可能失败”写成“已经失败”，或把“建议检查”提高为必须检查。
- 错误事实、可能原因和处理建议分别核实。连接超时不能直接改写成密码错误；纯措辞修改不得添加未经来源支持的处理步骤。

交付前逐段对照执行者、对象、条件、顺序、权限与结果，保留数值、单位、范围和限制。尤其核对“允许尝试但执行失败”的情况，避免把失败分支误写成未获许可分支。标点检查通过不代表语义保持；审阅时列出无法消除的歧义，改写时保留并指出需要核实的原句。

请求评估某项写作标准的合规性时，读取适用版本的标准原文并注明版本与覆盖范围。局部检查不得报告整体合规。
