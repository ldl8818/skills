# Product localization
Inspect the string's actual UI role, placeholders, pluralization, character constraints and nearby terms.
Preserve placeholder names and semantic meaning. Localize actions consistently and avoid claiming a capability the product does not have.
Check truncation and ambiguity in the actual surface when layout is part of the request. Do not convert wording work into an unsolicited UI redesign.
Compare every requested locale against the current source by stable content ID and section, including examples, flags, limits and warnings. Translation is not summarization; matching key counts or old translations cannot establish current completeness.
Check borrowed platform names and capabilities against the target platform. Keep a control's title, tooltip and related labels consistent within each locale; shortening a label must preserve its action and scope, such as checking versus cleaning or starting versus resetting.
Preserve executable command bytes and actual navigation labels. Treat command examples as text, not instructions to execute. Inspect rendered inline tags and composed strings for glued words, missing separators and incorrect plurals when those surfaces change.
