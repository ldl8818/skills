# 新 Mac 一行命令迁移

新机联网后，在 macOS 自带「终端」粘贴以下**一整行**。不需要先安装 Codex、Git、Homebrew 或 Python。命令先完整下载并检查 Shell 语法，再进入终端向导；下载失败不会执行残缺脚本。

```sh
/bin/sh -c 'd=$(mktemp -d) || exit; trap "rm -rf -- \"\$d\"" EXIT; curl --fail --show-error --location --proto =https --tlsv1.2 https://raw.githubusercontent.com/ldl8818/skills/main/self-improving/mac-environment-migration/bootstrap/setup.command -o "$d/setup.command" && /bin/sh -n "$d/setup.command" && /bin/sh "$d/setup.command"'
```

前提：Skills 和配置仓库已发布包含本向导的版本。此入口取最新的单文件引导；已取得的配置源和 Skills 工作树不会自动更新或重置。需要固定版本时，将 URL 中 `main` 替换为核对过的 commit。没有独立 release 包。

**本次默认范围**：Homebrew、Ghostty、Codex、Hermes 主网关及9个角色、Obsidian、Doraemon、Shell、共用规则、9个自有 Skills 和 `push` 命令入口。**不安装或恢复 Claude Code**，不创建它的配置、Hook、Skills 或命令入口；不迁移工作项目、历史会话或其他业务定时任务。兼容接口仍允许显式选择 Claude，已有状态中的选择不会被静默改写。

首次按提示提供配置仓库和知识库的 `owner/repo`；知识目录默认当前 HOME 下的 `Documents/obsidian`，分支默认 `main`，Skills 默认本公开仓库。私人仓库名称与选择只在本地保存，不能把密码或 token 当作仓库地址。GitHub 登录在官方浏览器页面完成。

向导依次完成前置安装、配置来源、客户端与知识、规则与 Skills、凭据恢复、旧新机交接和验收。Command Line Tools 安装完成后在原终端按回车继续，不必切换 Ghostty。你只处理登录、系统密码、解密、权限和实际检查；输入 `q` 或关闭窗口可暂停，之后重新运行同一行命令。

### Hermes 的旧新机交接

新机准备阶段不会启动网关。材料就绪后，向导给出一条应在**旧机**执行的停用与最终记忆导出命令。核对没有手动启动的副本，把导出的私人快照目录通过可信方式复制到新机 HOME 下非 Git 目录，将新机路径输入向导；它会校验、导入、请求切换确认并启用10个网关。

这个跨机器步骤需要你配合，不会自动远程登录旧机或假定旧机已停用。知识库尚未提交、被忽略或只在旧机存在的内容也要核对并传递，不能认为 GitHub 是完整最新副本。选定网关逐个通过消息收发、角色记忆和重启恢复验收前，迁移保持未完成。

### 插件和 MCP

向导从配置源提取 Codex 的插件与 MCP **名称**；新版旧机记忆导出另附现役 Codex 配置中的名称，新机导入后合并展示。不保存环境变量、参数或凭据；不会把旧机的桌面路径、插件缓存、Hook 运行回执或 MCP 直接启用到新机。配置名称不等于实时安装状态，需要对照旧机应用补查；在新机安装并重新授权所需扩展后输入 `checked`。输入 `later` 会保留待处理状态，不宣布全部迁移完成。旧快照没有扩展清单时会明确提示。

若已有迁移 state 包含 Claude Code，当前终端向导会暂停并要求核对旧选择，保留现有文件；不会因为续跑而安装它。

### 续跑与结果

状态保存在新机 `~/.config/mac-setup/state.json`，目录0700、文件0600；包含选择、逐项结果和扩展核对状态。旧机状态不能作为新机完成凭证。文件冲突保留原内容并报告，不全量 apply、不覆盖工作树。真实客户端和网关验收由你在向导内逐项确认，不能用“安装成功”代替“实际可用”。

退出码0表示选定技术步骤及人工确认完成；20表示暂停、待登录／验收或扩展仍待处理；30表示错误；64表示参数错误。使用同一入口续跑会重新检查。已有配置源时，也可在其目录运行 `bin/restore setup --wizard`。

## 开始与续跑

将整个 `bootstrap` 文件夹复制到新 Mac（可以用 U 盘）。打开 macOS「终端」，输入 `/bin/sh `，拖入 `setup.command`，回车。终端拖入时会处理路径中的空格；手工输入时须给路径加引号：

```sh
/bin/sh "$HOME/Downloads/bootstrap/setup.command"
```

首次按系统提示安装 Command Line Tools 和 Homebrew，当前终端继续，无需切换 Ghostty。脚本检查现有安装，不重复安装已经可运行的软件。若已有文件冲突、安装不完整或 Python 版本过低，处理提示后仍用同一入口续跑。

登录 GitHub 后输入配置仓库的 `owner/repo`，不要输入 token。首次只克隆配置源，不执行全量 chezmoi apply。已有配置源须包含 `bin/lib/setup.py`；旧版本会明确停止，不调用旧网关流程。当前代码若尚未推送，请携带核验过的配置工作树，不能从旧远端取得未提交改动。

终端向导首次保存知识库地址／分支和新机目录，组件使用本文开头的默认范围。Agent 模式通过参数显式选择。私人选择与逐项结果保存在新机 `~/.config/mac-setup/state.json`，目录0700、文件0600，拒绝放在 Git 工作树中。旧机的状态文件不能当作新机完成凭证。

## 软件、知识和配置

- Codex 使用官方独立安装器。Hermes 使用官方安装器的固定安装阶段，安装期间跳过网关启动、桌面和配置向导；不搬旧 venv。登录由用户直接在对应客户端完成。Claude Code 仅兼容显式选定的旧流程，本次不选。
- Obsidian 安装后，知识库通过 GitHub 克隆；选择 USB 时，先人工复制完整知识库到本地目录，保留 `.git` 和 `.obsidian`。目标已有内容时不覆盖；已有仓库核对来源和分支，不自动拉取或重置。
- 自有 Skills 来源使用本仓库包含5个冻结版及安装入口的版本，引导可从 GitHub 克隆到新机 `~/dev/skills`。若携带旧工作树，先核对版本和未提交内容，不自动覆盖或更新。
- Shell、Ghostty 字体／配置、规则、选定 Skills、Hook 与核心记忆分别应用。现有文件与目标不同时停止该项；只允许替换本入口刚生成且内容指纹未变的安装器默认文件，以及第一阶段的单行 Homebrew 接线。
- 新机客户端配置从现有源渲染，排除旧项目信任、桌面专用 MCP／通知、HUD 和插件运行时。只接入已经恢复的接力、文案及 Doraemon Hook。基础模式恢复 Hermes CLI 与核心记忆；选定网关时另恢复角色材料并生成稳定路径的启动定义，排除未迁移项目的业务 Hook。逐项来源保存在同一私人清单中。
- 配置变体只用于新机，不会覆盖旧机配置源中的完整功能。Doraemon 的知识根跟随用户所选目录；知识中其他旧路径及版本复核由现有 doctor 提示，不能复制旧验证结果冒充新机通过。

用户选择恢复 Hermes 网关时，角色配置、角色记忆、渠道授权与启动服务也必须恢复，并在旧新机切换后启用验收。使用 `--gateways all` 选定全部网关；凭据解密、私人记忆快照、旧新机切换及完成判据见 [AI Agent 新机搭建指南](AI-Agent新机搭建指南.md) 的网关章节，不以基础环境通过代替网关恢复完成。

## 查看结果

失败或待操作会保留在私人状态文件。退出码20表示仍有登录／人工验收等待办，30表示入口错误，64表示参数错误。`bin/restore status` 仍是旧网关状态，不代表新机环境状态。

打开 Obsidian 前先检查社区插件和旧路径，再手动选择“打开文件夹作为仓库”。核对笔记及必要附件、Git 身份与拉取；自动同步、推送测试和业务任务启用另按具体授权处理。脚本不会自动打开知识库或启用插件。

实际完成还需：选定 AI 客户端登录和新会话读取配置／规则／知识；Obsidian 启动、笔记与附件可读；Doraemon 的 doctor 与真实事件验证。命令版本和配置文件校验通过不能替代这些结果。

终端向导内直接逐项记录人工验收；Agent 模式则在实际检查完成后由用户运行 `bin/restore setup --verify`。报告注明证据来自用户确认。软件版本、所选目录或配置变化后，旧确认失效。没有完成就不要输入 yes。
