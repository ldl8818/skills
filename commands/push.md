# push

用户调用此命令即授权提交并推送当前任务，并明确委派低成本模型执行。附加范围：$ARGUMENTS

## 主 Agent 准备

1. 从当前对话明确任务范围，再核对工作区、适用 AGENTS.md、ROADMAP.md、Git 分支、暂存区及未暂存差异。默认仅当前任务；用户明确“全部”才包含其他已确认归属的改动并按主题分批。新会话无法确定范围时，只问缺失的范围，不把所有 dirty 文件当成本任务。
2. 同步受影响文档，完成相称检查；已有验证在内容、依赖、配置和环境仍等价时复用。纯文案走局部检查，不升级成全仓审计。发现无关暂存或同文件混合改动时保留它们，不能整文件带入或擅自清空暂存区。
3. 向执行模型交付：仓库绝对路径、任务目的、允许提交的精确文件／片段、禁止触碰的改动、已通过及仍需执行的检查、当前 HEAD 和目标远端／分支。范围有实质歧义先澄清；明确后不重复请求提交或推送确认。

## 低成本执行

- 固定使用 `gpt-5.6-luna`，推理档 `medium`。支持指定模型的子 Agent 工具时，派发一个短上下文任务，明确模型和推理档；不继承完整历史，不继续转派。主 Agent 等待期间整理验收依据，避免并发修改同一仓库。
- 没有可指定该模型的子 Agent 工具时（例如 Claude Code），把上述交接与本节要求写入本任务临时文件，通过标准输入调用 `codex exec -m gpt-5.6-luna -c 'model_reasoning_effort="medium"' -C <repo> -`。参数按 argv 安全传递，用户文本不得拼接成 Shell 代码；沿用现有登录、权限和 Hook，不添加绕过开关。
- CLI 或指定模型不可用时报告阻塞，不悄悄改用当前高成本模型，也不安装或改写模型配置。
- 写入前重新核对 HEAD、分支、工作区和远端，发现并发变化先对账。检查本次暂存区的文件名及内容，拒绝真实环境配置、密钥和私人数据；无密钥示例模板按项目规则允许。
- 精确暂存任务范围，禁用 `git add .`、`git add -A`。保留已有无关暂存；不能可靠隔离时停止并返回具体冲突。提交使用 `TZ=Asia/Shanghai git commit`，中文说明，前缀按全局／项目 Git 规则，不加 Co-Authored-By。
- 只向已确定的远端／分支普通 push，不创建 PR、不发评论、不部署、不 tag、不 force-push、不 reset／clean／rebase。远端目标缺失或含尚未授权的历史提交时返回说明；push 拒绝或结果未知先查远端，不盲目重试或改写历史。
- 返回实际使用模型、提交 SHA、提交文件、检查结果、推送目标及结果、剩余改动；未完成项明确标注。

## 主 Agent 验收

亲自检查提交内容与授权范围、当前 HEAD、`git ls-remote` 返回的目标分支 SHA，以及剩余工作区改动；不能仅采信执行模型的完成声明。已有 CI 按项目要求核对对应提交的检查，区分推送成功、CI 成功和未验证的真实运行效果。同步必要进度后简短交付：提交、推送、验证及未完成项。
