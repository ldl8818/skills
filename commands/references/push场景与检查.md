# push 场景与检查

供命令分级有疑问时查阅。先按实际影响判断，不按扩展名、行数或“只是小改”定档；以下是常见场景，不是每次逐条执行的检查表。所有低风险场景仍须满足命令正文的低风险条件与最低检查。

## 可走低风险的场景

| 场景 | 本次相称检查；等价结果可复用 |
| --- | --- |
| 普通文案错字、标点、段落调整 | 局部 diff、排版；确认不改变承诺、规则或操作含义 |
| 非功能注释、文档格式整理 | 确认不是工具指令、生成标记或可执行示例 |
| 文档标题、内部链接和锚点调整 | 检查受影响链接及入口引用 |
| 现有信息的翻译修正 | 检查占位符、复数规则、转义及含义一致 |
| 局部颜色、间距、圆角、字体调整 | 受影响页面的现有渲染证据；必要时补相关视口检查 |
| 图标、静态图片替换 | 引用、资源可加载、尺寸与相关视觉效果 |
| 不改变含义的按钮文案 | 文本溢出、可访问名称与原交互保持一致 |
| 函数内局部变量重命名 | 静态引用、相关 lint／类型检查；排除字符串反射 |
| 私有函数或局部文件重命名 | 直接引用、导入及相关构建检查；确认无动态加载或对外路径 |
| 受影响范围明确的格式化 | 确认没有语义变化，复用对应解析／构建结果 |
| 已授权且引用明确的静态资源清理 | 确认无静态／动态／构建注册引用；删除授权须已覆盖 |
| 独立的多个低风险任务均已完成 | 主 Agent 一次明确分批范围与完成证据，直接逐批精确提交 |

## 进入标准档的场景

| 场景 | 主 Agent 需要定向检查的具体风险 |
| --- | --- |
| AGENTS、Skill、命令、权限或验收说明变化 | 实际路由、授权及执行行为，不能按纯 Markdown 免检 |
| 安装命令、脚本、示例代码或默认配置变化 | 可执行行为、配置兼容性与受影响使用流程 |
| 法律、价格、结算、安全提示文案变化 | 业务含义与承诺；必要时澄清不能代决的内容 |
| UI 点击、提交、导航、焦点或键盘行为变化 | 相关交互与可访问性，不只看截图 |
| UI 全局样式、共享组件、响应式结构变化 | 直接消费者及受影响视口，避免局部正常而其他页面回归 |
| CSS 改变隐藏、层叠、点击区域或内容顺序 | 信息可见性和交互，即使只有一行也不能只做颜色检查 |
| 公共接口、导出符号、路由、配置键重命名 | 调用方、序列化、持久化与兼容性 |
| 动态导入、反射、插件注册或大小写文件重命名 | 静态搜索不能覆盖的加载路径及目标平台行为 |
| 共享逻辑、业务判断、并发、性能或数据流变化 | 直接调用方、结果使用方、关键失败路径与相关回归 |
| 依赖版本、锁文件、构建、CI 或发布配置变化 | 依赖与产物变化、必需门禁以及外部发布授权 |
| 数据库、迁移、认证、密钥或生产相关改动 | 授权与数据保护；标准档不扩大授权 |
| 生成文件、二进制或快照更新无法直接判断含义 | 生成来源与重建检查，不以快照通过代替正确性 |
| 同文件混合任务、无关已暂存项或任务间有依赖 | 分批隔离、提交顺序、中间提交及最终结果是否可用 |
| 主 Agent 缺失任务上下文或完成证据不明 | 先补足范围；不能把所有 dirty 文件当作已完成 |
| 项目明确要求独立复核或特殊发布门禁 | 遵循项目更严格要求，不能用低风险标签豁免 |

## 异常与边界处理

| 场景 | 动作 |
| --- | --- |
| 部分任务未完成或状态不明 | 按正文退回本次任务；无关任务未完成本身不强迫本次低风险任务升级 |
| 当前任务仍缺必要验证 | 主 Agent 补相称检查；无法通过则保留并报告，不能提交半成品 |
| 显式要求全部／指定文件 | 范围以用户指定为准，风险和验证要求仍保留；半成品快照必须有明确授权 |
| HEAD、分支、暂存区或工作文件并发变化 | 暂停相关写入并对账，只使受影响范围及检查失效 |
| 已有本地提交尚未推送 | 核对完整待推送提交集合的授权，不只检查本次新提交 |
| 无文件改动 | 仅推送已有已授权提交；无待交付内容则直接报告 |
| 分支或远端缺失、受保护分支限制 | 返回具体缺口，不擅自创建目标、PR 或更改保护配置 |
| Hook 修改文件、检查失败或产生额外差异 | 停止后续推送，定位变化并重新检查受影响部分，不跳过 Hook |
| Hook 提交后更新暂存区或留下格式化文件 | 核对提交与剩余状态，不能自动再提交或清空 |
| push 被拒绝或网络超时 | 先查远端实际结果；不盲目重试、rebase 或 force-push |
| 远端 SHA 与提交不同 | 验证祖先关系区分远端前进与未送达；证据不足标记待核实 |
| 多批仅部分提交／推送成功 | 返回逐批 SHA 与状态，续跑先核对已完成批次，不重复提交 |
| CI pending／缺失 | 无明确等待门禁时查询一次后报告，不轮询；已知无相关 CI 则不查询 |
| CI 失败 | 看对应 SHA 和失败摘要；普通 push 报告推送与 CI 各自结果，不自动开始修复。项目门禁或明确 CI 修复任务按原要求继续 |
| CI 环境与本地不同 | 可能是依赖、权限、网络或跨平台缺陷；依据失败步骤归因，不能一概视为环境噪声 |
| 纯文案且无行为影响 | 只做本次差异、敏感信息、格式、精确暂存和 Git 结果检查；无明确门禁时不跑全仓检查 |
| 本地相关必需检查失败 | 不能用远端环境差异解释或跳过；先定位本地失败，保留未完成状态 |
| 执行证据不完整或自相矛盾 | 主 Agent 只补查缺口；实质风险升级标准档 |
| Git、终端工具或认证不可用 | 如实报告具体阻塞，不启动其他模型兜底或绕过权限 |

## 速度与质量的取舍

- 所有 push 由主 Agent 直接执行，省去模型启动和交接；暂存区、敏感信息、必要验证和远端检查仍保留。
- 同一已验证改动不因进入 push 阶段重跑检查；Git 工作区和远端等易变化事实在实际写入／推送时核对。
- 主 Agent 连续处理全部已确定批次，检查按直接影响选取；不强制全仓扫描、全套测试或另建执行 Agent。
- 场景不匹配时判断真实影响：能证明满足低风险条件即可低风险，不能证明时只对具体疑点升级，不要求穷举所有假设风险。
- 记录真实检查和等待证据；不以固定秒数、行数或文件数决定跳过验证，不承诺未经对照测量的提速比例。
