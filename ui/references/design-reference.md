# Project visual context
Read current tokens, comparable components and the actual screen. Identify the user's primary task, information hierarchy and expected density.
For a mature product, use existing type scale, spacing, controls and color roles. For a new surface, derive choices from audience and content rather than a prescribed aesthetic.
Compare hierarchy, reading order, alignment, wrapping and state visibility. Use realistic content lengths and values.
Keep natural wrapping by default. Before shortening a short last line, inspect container width and forced breaks; remove repetition only when meaning and qualifications survive. Do not shrink type, narrow the container or add manual breaks merely to equalize lines. Apply a requested line budget to its named component.
Fonts, cards, gradients and motion are choices to justify from the product context, not universally required or forbidden.
Check the result in its actual renderer and relevant viewport. Avoid declaring success from CSS or component source alone.
