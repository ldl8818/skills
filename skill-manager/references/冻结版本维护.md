# Waza 来源 Skill 的维护

本仓库维护六项 Waza 来源 Skill：`check`、`health`、`hunt`、`think`、`ui`、`write`。六项沿用已选择的 `main` 通道，源头基线为 [Waza main 固定快照](https://github.com/tw93/Waza/tree/b55809013be84b1f59418b557c1e8bad66380705)，commit 为 `b55809013be84b1f59418b557c1e8bad66380705`；当前最新发布 tag 仍为 [v3.40.0](https://github.com/tw93/Waza/releases/tag/v3.40.0)，两者分别核对，不以发布 tag 代替 main 更新。每个一级目录是唯一源码真身；客户端目录只放直接指向它的单跳软链。

`check`、`health`、`hunt`、`ui`、`write` 是独立维护的本地冻结版，当前 `hunt` 的本地版本为4.3.2，`check` 为6.2.0，`health` 为4.2.0，`ui` 为4.2.0，`write` 为4.3.0；`think` 保留该基线的完整原版，不另编本地版本。主干保留 Waza MIT 许可；check 的主来源元数据记录已完整对账的 Waza 合并基线，Alibaba v1.12.13作为次级工具来源记在 `check/NOTICE.md`，其接入材料继续保留 Apache-2.0 许可，不能随主次调整重新标成 MIT。

`check` 根据行为风险选择轻量直查或深入审查，不按文件数量或扩展名机械分档。轻量路径不要求 OCR、额外清单或整套规则；复杂路径围绕业务预期、调用关系和关键场景检查，按需使用 Delegate。新增事故账本校验与审查回放入口，按项目是否维护账本使用，不自动创建项目档案。路径风险分层沿用项目明确门禁，既有授权内不重复审批，也不按固定轮数终止修复。动态范围与必要修复、验证和交付规则保留；全文审计不能用变更预览代替，工具漏选不取消任务范围。`hunt` 继续负责故障诊断，需要审查修改时衔接 `check`。

宿主审查及 Delegate 无需独立模型 API；在使用订阅的 Codex 会话中沿用当前会话。完整 OCR 仅在明确选择且模型通道已获授权时使用，不能将 Delegate 标成完整引擎验收，也不能因缺少 API 阻塞普通审查。冻结安装器只连接源码入口，不下载 OCR 或配置凭据；普通审查不得提取宿主登录令牌或接入 OAuth 代理。Delegate 接入见 check 的 `references/open-code-review.md`；完整引擎与授权安装按需读 `references/OCR完整引擎.md`。

`metadata.version` 表示本地版本；`github_url`、`github_hash`、`github_path` 表示当前完整对账的上游合并基线，不表示内容仍与上游一致。`update_policy: frozen` 阻止 skill-manager 的单项、批量及指定分支更新覆盖。冻结不是文件系统写保护，外部强制安装器仍可破坏入口，因此不要对这些名字运行上游安装／更新命令。

## 安装与恢复

先把自己的 skills 仓库检出到选定目录，再从仓库根运行：

```bash
python3 skill-manager/scripts/install_frozen.py --repo "$PWD"
```

该命令不下载、不拉取、不更新源码，只连接共享入口、Claude 和 Codex 入口。源文件缺失、合并回执缺失或失效、未冻结、同名真目录或不同目标的软链都会报冲突并保持原状。已有正确入口可重复运行。迁移旧真目录须先核对内容、备份并明确处理冲突，不能用强制安装替代迁移。

`think` 独立维护于仓库的 `think/`，安装方式见其 [README](../../think/README.md)，不属于上述冻结安装器的恢复集合。更新时核对 `skills/think/` 的完整文件清单与字节内容，并核对仓库根 MIT 许可；目前为 `SKILL.md` 及3份参考文档。来源及安装说明归本地 README，不修改原版路由与正文。旧 `learn`、`read` 不再安装，不保留别名或占位。其他来源的 Skills 不在此集合内。

## 完整合并上游更新

冻结用于阻止自动覆盖。用户明确要求更新时，完成源头最新版与本地特有能力的合并；不得把自动更新拒绝当作任务完成，也不得只摘录适用条款。

定制已被新版支持、仍需保留或部分支持的判断，统一按[升级与定制合并](升级与定制合并.md#定制判断与合并)处理；下述步骤维护本集合特有的来源、许可、冻结与登记要求。

1. 核对实际作用域、工作区改动、来源 URL、`github_path`、旧来源 commit 与目标通道；`check --include-frozen` 的比较结果只用于定位源头变化。明确用户所说的最新版是发布版还是主分支，已有通道沿用，不静默回退。
2. 在任务隔离目录取得完整旧上游与新上游快照，同时保存本地现状。比较旧上游、本地、新上游三方内容；清点新快照的所有文件，不只比较上游新增的几行。旧基线与新上游相同也要核对本地是否缺文件或丢失原有能力。
3. 以完整新上游为合并基础，逐项处理新增、修改和删除；采用已满足定制用途的新原生实现，保留尚需的本地能力，核对路由、授权、安全边界及适配器。遇到冲突时依据用户和项目的有效约束解决，明确每项适配原因；不得用泛化的“本地定制”替代整份入口、参考资料或模式。语义不清时保留具体待核实项，不伪造完成。
   三个路由字段的原文与增补要求以 [Skill 入口的路由字段](../SKILL.md#路由字段)为准。逐项核对 `description`、`when_to_use`、`dispatch_intent`，不能只核对其中一个；原文完整保留后，本地触发词可在合适位置插入。不得先改写、翻译或筛选上游内容，也不得用 `keep_local_description` 绕过。
4. 完成后将 `github_hash` 更新为已完整对账的新合并基线；原来源与历史改造仍可从 Git 和许可／来源说明追溯。保持 `update_policy: frozen`，本地版本独立递增，不冒充上游版本。许可、来源和本地特有文件必须保留。
5. 为每项改动的上游文件准备适配理由 JSON，键为 `skill/path`，值为理由列表；需要改名时可使用对象：`{"reason":["明确的适配理由"],"heading_map":{"## Source heading":"## Local heading"},"local_path":"保留内容后的目标路径"}`。`heading_map` 与 `local_path` 按需填写，不能将多个源章节或文件合并映射成同一项。使用下列命令登记并核验：

   ```bash
   python3 skill-manager/scripts/audit_upstream.py --repo "$PWD" \
     --upstream <上游Git仓库> --adaptations <适配理由JSON> --record
   python3 skill-manager/scripts/audit_upstream.py --repo "$PWD" \
     --upstream <上游Git仓库>
   python3 skill-manager/scripts/verify_frozen.py --repo "$PWD"
   ```

   `--record` 只在完整源文件均存在、改动均有理由且元数据与候选 HEAD 一致时写回执。它不替 Agent 完成语义合并；不得为了通过检查而批量补写空泛理由。回执记录逐文件源／本地哈希、改动范围、Markdown 章节映射和本地特有文件；每个源章节必须保留，改名时须明确一对一映射，不允许以泛化适配理由跳过整节。安全的源仓库内部链接以普通文件内容核对；合成环境测试资料可明确映射到 `.env.example`，不得导入真实环境配置。文件缺失、未说明的适配、源快照不一致或登记后漂移均须先解决。
6. 验证完整模式与参考资料、本地特有能力、授权／路由正常与失败场景，并运行相称脚本回归。脚本测试与源文件覆盖分别报告；静态文字或哈希不能证明真实模型行为。交付说明源头 commit、完整覆盖数、必要适配、实际测试和未验边界，只有上述检查满足后才报告合并完成。

### 日常检查与后续修改

`audit_upstream.py --repo "$PWD"` 不联网，只核对现存文件与回执；它不判断远端是否有更新。`scan_and_check.py --include-frozen` 分别报告上游引用比较与合并回执状态。结构校验、版本字段或远端 commit 相同都不能代替源快照核对。

后续修改已登记 Skill 时，相关行为验证通过后，用同一固定上游快照重新核对并登记有依据的本地差异。正常编辑仍遵循原授权；不得为规避漂移检查而禁用完整性验收。程序无法判定改写是否保留全部语义，Agent 必须审阅回执中的差异和原文。

Git 提交本身不会从原作者下载代码。需要防范的是自动更新、安装器重装和恢复入口重新指向原作者。chezmoi 应调用上述本地入口，不再用上游安装器覆盖这些名字。未提交的本地改动尚不能靠远端新机恢复。

## 验证

```bash
python3 -m unittest discover -s skill-manager/tests
python3 -m unittest discover -s check/tests
python3 -m unittest discover -s health/tests
python3 skill-manager/scripts/verify_frozen.py --repo "$PWD"
```

静态路由案例在 `skill-manager/references/waza-routing-cases.json`，用于后续客户端行为评测；结构验证不能证明模型每次都会正确选择。旧会话的 Skill 清单可能仍保留旧内容，磁盘切换后需新会话确认。
