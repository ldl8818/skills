# 定制冻结版的维护

本仓库的 `check`、`health`、`hunt`、`ui`、`write` 是独立维护的本地冻结版，当前 `hunt` 的本地版本为4.2.0，`check` 为5.0.0，`health` 为4.0.2，`ui`、`write` 为4.0.1。每个一级目录是唯一源码真身；客户端目录只放直接指向它的单跳软链。`check` 当前主体来自 Alibaba OpenCodeReview，保留 Apache-2.0 许可及 Waza 留用材料的 MIT 许可与历史；其余四个保留 Waza MIT 许可。

`check` 采用 Alibaba 官方 Skill 的完整审查主流程，默认 `ocr review`，明确的全文审计使用 `ocr scan`；不新增另一个阿里 Skill。按任务动态确定代码、文档、测试和未跟踪文件的范围，独立清单与 OCR 结果对账。原有授权内修复、必要验证和交付规则保留；`hunt` 继续负责故障诊断，需要审查修改时衔接 `check`。

完整 OCR 依赖单独安装的原生二进制和已配置的模型端点，冻结安装器不会下载、升级或配置它们。缺少依赖时报告“完整 OCR 未运行”，可继续明确标注的宿主检查；不能把 preview、delegate 或宿主检查算作完整 OCR 验收。接入和安装契约见 check 的 `references/open-code-review.md`，当前来源与 Waza 历史见 `check/NOTICE.md`。

`metadata.version` 表示本地版本；`github_url`、`github_hash`、`github_path` 表示当前采用的上游来源基线，不表示内容仍与上游一致。`update_policy: frozen` 阻止 skill-manager 的单项、批量及指定分支更新覆盖。冻结不是文件系统写保护，外部强制安装器仍可破坏入口，因此不要对这些名字运行上游安装／更新命令。

## 安装与恢复

先把自己的 skills 仓库检出到选定目录，再从仓库根运行：

```bash
python3 skill-manager/scripts/install_frozen.py --repo "$PWD"
```

该命令不下载、不拉取、不更新源码，只连接共享入口、Claude 和 Codex 入口。源文件缺失、未冻结、同名真目录或不同目标的软链都会报冲突并保持原状。已有正确入口可重复运行。迁移旧真目录须先核对内容、备份并明确处理冲突，不能用强制安装替代迁移。

旧 `think`、`learn`、`read` 不再安装，不保留别名或占位。其他来源的 Skills 不在此集合内。

## 评估上游更新

1. 运行 `python3 skill-manager/scripts/scan_and_check.py --include-frozen`。这只查询上游引用；冻结项一直保持 frozen，不进入自动更新清单。commit 不同只表示有差异，不能推导哪个版本更好。
2. 在任务的 `.tmp/` 隔离目录拉取上游，记录拟评估的完整 commit。用各 Skill 的 `github_hash` 作为来源基线，比较“上游基线→上游候选”的变更，再与当前本地文件逐项比较；不得把本地4.0.1与上游版本数字直接排序。
3. 只合并明确适合当前边界的内容。保持冻结标记、单源路径和本地路由，不复制整个上游目录覆盖本地。遇到上游删除或改名，也先按实际调用与当前需求判断。
4. 运行受影响脚本测试、引用和路由检查，再递增本地版本。`bump_skill.py` 可以登记内容指纹；不要手填假上游版本。
5. 原始 `github_hash` 保留为来源证据。后续部分合并的候选 commit、实际采纳范围和拒绝理由写入相关 Git 提交说明；只有完整采用新基线时才改变来源字段。正式提交按任务授权执行。

Git 提交本身不会从原作者下载代码。需要防范的是自动更新、安装器重装和恢复入口重新指向原作者。chezmoi 应调用上述本地入口，不再用上游安装器覆盖这些名字。未提交的本地改动尚不能靠远端新机恢复。

## 验证

```bash
python3 -m unittest discover -s skill-manager/tests
python3 -m unittest discover -s check/tests
python3 -m unittest discover -s health/tests
python3 skill-manager/scripts/verify_frozen.py --repo "$PWD"
```

静态路由案例在 `skill-manager/references/waza-routing-cases.json`，用于后续客户端行为评测；结构验证不能证明模型每次都会正确选择。旧会话的 Skill 清单可能仍保留旧内容，磁盘切换后需新会话确认。
