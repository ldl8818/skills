# 公众号正文与跳转

已知公众号原文链接时先使用合适的专用读取能力。OpenCLI `weixin/search` 有时返回 `weixin.sogou.com/link?url=...` 中转链；它不是文章正文地址，可能需要浏览器执行跳转。

## 核对目标与正文

1. 保留搜索结果的原始链接、标题、公众号名和可用时间，判断是中转链还是 `mp.weixin.qq.com` 原文。
2. 已有原文且用户明确要求保存时，先执行下节的 `weixin/download` 并验实际文件；只阅读时使用适用的专用正文来源，不为拿同一内容额外归档。已有足够正文或文件时不再启动浏览器重取。
3. 只有中转链需解析时，优先使用 OpenCLI Browser 等适用 OpenCLI 能力，等待真实跳转并观察落地 URL；取得原文后回到正文／归档动作，不自动改为全程 DOM 提取。验证页、登录页和中转页不能交付为正文；OpenCLI 连接阻塞按对应恢复条件处理，不直接换 Ego。
4. 专用动作的结构或解析缺陷仍影响目标时，先按 [适配器修复与浏览器兜底](failure-domains.md#适配器修复与浏览器兜底) 修复。通过门槛后，才按 [浏览器选路.md](浏览器选路.md) 使用通用浏览器定向提取标题、作者、发布时间和正文。历史页面常见选择器为 `#activity-name`、`#js_name`、`#js_content`；节点不存在时重新观察 DOM，不因旧选择器失效就声称文章不存在。
5. 正文是否完整按文章与任务判断，不设统一千字门槛。完整短文可交付；长文片段明确标部分，缺口影响问题时再补充。
6. 按正式浏览器 Skill 收尾本任务资源，不调用旧 API 或回收其他会话页面。

过去曾观察到中转链经普通 HTTP 返回验证码页、下载命令只接受原文 URL；这些是带版本与环境条件的经验，不是所有未来实现都无效的证明。当前调用仍以 URL、内容与错误状态验收，避免反复尝试同一已失败中转路径。

## 显式归档

用户明确需要保存时优先选择 OpenCLI `weixin/download`。先从当前注册表和帮助确认 `access`、输出目录和图片选项，再传真实原文 URL；需要配图时启用 `--download-images true`，仅保存正文时用 `false`：

```bash
node scripts/opencli-run.mjs weixin download --url "<mp.weixin.qq.com 原文URL>" \
  --output "<指定目录>" --download-images false -f json --window background
```

[已核对实现](https://github.com/jackwener/opencli/blob/b06ab7780e73d3021e12e0f170086c2d55675776/clis/weixin/download.js#L342-L352) 遇验证页会返回含 `title: Error` 和失败 `status` 的非空结果行；exit 0 或非空数组仍不能证明归档成功，应核对实际状态、正文与生成文件。

真实可访问 URL 可能含签名或跳转参数；保留在 `access_url`，不要为了去重或美化覆盖它。核对实际编码、尺寸与数量，不按扩展名猜格式；保存操作遵循用户现有授权、范围与文件保留规则。

页面明确显示链接过期时，不重复提交同一个签名链接。可通过已授权的搜索重新定位同一篇文章，核对标题、公众号、发布时间与正文身份后更新本地访问记录，再执行适用的归档动作；不能换成相似文章。明确的验证码或账号挑战沿用停止边界，不按链接过期处理。
