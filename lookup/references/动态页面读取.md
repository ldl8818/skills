# 动态页面读取

在已选浏览器中遇到加载中、登录提示、目标缺失、iframe 或 Shadow DOM 时读取。浏览器选择归 [浏览器选路.md](浏览器选路.md)，操作与等待 API 从当前正式接口发现；本参考不提供另一套浏览器服务。

## 目标内容与等待

1. 根据请求确定可核对的目标：文章标题与相关段落、报表列与行范围、指定对象详情或操作后的状态。优先等待这些内容，不以固定字数、页面标题、HTTP 200、`readyState` 或整站网络空闲代替。
2. 首次导航后检查当前 URL、目标节点与相关正文。导航超时也要先看原页面实际状态；已经取得足够内容时直接验收，不重开页面或重派原动作。
3. 目标尚未出现时，按下表判断。每次观察只取足以判断状态的 URL、加载标记和目标内容，不反复输出整页 DOM。

| 观察结果 | 后续动作与结束条件 |
|---|---|
| 目标内容已出现且与请求相符 | 按要求提取；无需等广告、推荐区或所有网络请求结束 |
| 初始 `about:blank`、骨架屏、普通跳转或异步加载，尚无明确阻碍 | 在同一页面有界等待目标节点／文本；变化后重新判断目标身份 |
| 页面稳定但所需内容缺失 | 定向检查相关折叠区、分页、frame 或媒体；不把继续空等当恢复 |
| 有登录入口／弹窗，但所需内容已可完整读取 | 读取已获授权的内容；不为无关登录提示要求用户操作 |
| 明确的认证要求、验证码、权限拒绝、账号风控或用户接管阻断任务 | 停止相关自动操作，说明缺少的具体内容；按现有交接流程处理，不自动解挑战或换账号绕过 |
| 等待预算耗尽，仍无足够内容 | 保留已有证据和当前阻碍；有可用部分则交付 `partial`，否则报告 `error`，不推断内容不存在 |

等待使用当前接口支持的有限超时，并计入本次读取的总预算。已有明确时限就沿用；没有时按站点经验和任务成本选一个短且有限的窗口，不固定套用统一秒数。普通跳转或加载变化不自动重置总预算。优先条件等待；只能轮询时限制总时长和频率，避免无间隔循环。

等待和重试分开处理：观察同一页面不是重新提交动作；等待超时也不证明前一动作已取消。重试与换路仍遵循 [failure-domains.md](failure-domains.md)。

## 页面结构、访问上下文与状态

- 先定向观察目标容器、链接和控件，再决定读取或交互。折叠文字、轮播非当前项可能已经加载在 DOM 中，可读取任务相关部分；这只证明内容存在，不证明用户当前可见、布局正确或媒体已渲染。读取不得绕过登录、付费或权限控制。
- 所需内容必须展开、翻页或滚动才可取得时，用已授权的正常页面交互推进；操作后检查具体内容或状态变化。点击回执、事件已发出和 `isTrusted` 都不能单独证明成功，也不保证免于反爬。
- 页面重渲染或快照更新后，重新定位目标节点与引用；旧 ref、选择器命中或句柄可能已失效，甚至指向其他元素。继续读取或操作前核对节点类型、所属容器和目标内容，不只看工具调用是否成功。
- 导航优先使用页面实际生成的链接或正常入口，保留必要 query、fragment 与访问上下文；完整 URL 通过结构化参数或单一 argv 传输，不手拼到另一层查询串或 shell source。用于展示的去参数 URL 不能覆盖 `access_url`；分享与引用时不泄露会话或访问令牌。
- 页面报“内容不存在”时，核对原始完整链接、当前落地页和访问条件；证据指向上下文缺失时，从已授权的站点入口恢复定位，不猜参数、伪造 token 或循环盲试。确认删除／无匹配前，不把访问失败写成目标不存在。

## iframe 与 Shadow DOM

先核对目标是否位于 frame 或组件内部；父文档无匹配节点不等于目标不存在。只发现与任务相关的容器，不扫描无关 frame 或页面数据。

| 边界 | 可用读取方式与限制 |
|---|---|
| 同源 iframe | 当前接口的 frame 定位；允许页面求值时也可从可访问的 `contentDocument` 定向读取 |
| 跨源 iframe | 使用当前工具正式暴露的 frame／独立执行上下文能力；父页面 `contentDocument` 不可读不是全文为空，普通 JS 递归不能穿透同源限制 |
| open Shadow DOM | 使用工具支持的穿透定位，或沿已观察到的 `shadowRoot` 进入相关组件；普通 `querySelector` 不自动跨边界 |
| closed Shadow DOM | 页面 `shadowRoot` 通常为 `null`；按工具实际能力或可见界面取证，不宣称通用递归可读取 |
| 嵌套、未加载或已导航的 frame | 核对 frame 列表是否递归、是否含 shadow root 内的 frame；逐层定位，加载／重渲染／导航后重新确认标识，不能沿用过期 frame ID |

- 在已授权的目标 tab 内，用正式接口确认 frame 的父子关系，再以名称／实际 URL 和内容定位目标；不靠名称或域名推断页面属于本任务。frame 的 `src` 可能与当前 URL 不同。工具返回的 frame 列表可能只含主文档的直接子项，不据此声称所有嵌套内容都已读取。
- 优先用 frame 内元素定位进行交互。确需坐标时，确认当前截图、视口、所属 frame 和工具的坐标单位／换算规则；滚动、缩放或导航后重新定位。不得把 frame 局部坐标直接当主页面坐标。
- 隔离执行环境可能能读 DOM 却看不到页面 JS 全局变量；不能把变量缺失当页面没有数据，也不调用未知内部函数来补救。
- 接口未暴露所需 frame 能力，或结果经核对不属于目标 frame 时，改用能确认层级与目标身份的全页快照／可见界面取证，仍不足则说明缺口；不反复猜旧引用，不自动安装 Proxy、改调试设置或另开 frame URL。另开子页面可能失去嵌入时的认证与上下文。

## 站点经验复用

沿用 [search-routing.md](search-routing.md#本机历史与站点经验) 的唯一存储入口。记录已验证的公开选择器、目标就绪条件、frame 层级、正常入口和已知限制，并附日期、适用工具／版本；不保存私人正文、带凭据的 URL 或真实访问令牌。

经验只是候选提示。与当前页面冲突时，以当前证据重新定位，验证新方式后再更新对应经验；一次失败不写成永久不可用，也不为普通查询强建经验文件。
