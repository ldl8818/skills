# 失败作用域与结果验收

遇到失败时先保留命令结果，再判断哪一条依赖坏了。不同工具可能共享浏览器、账号或网络；同一个 OpenCLI 的不同站点动作也不一定一起失败。

## 作用域

| 层或结果 | 证据 | 本任务的处理范围 |
|---|---|---|
| 本地执行环境 | 沙箱或联网策略拒绝；仅当前执行环境出现 `offline`／`fetch failed` | 先定位执行环境与远端服务的区别；已有授权且宿主允许时，可在允许联网的执行环境完成一次有依据的验证。此类失败不证明服务停机、限流或额度耗尽；真实权限拒绝仍停止相关操作，不换工具绕过 |
| 浏览器进程／网络 | 进程不可达或已确认共同网络失败 | 暂停依赖该进程／网络的候选；检查已授权且实际独立的通道 |
| bridge + Profile | 结构化 `BROWSER_CONNECT`、明确的 Profile 未绑定／断连／错配，或原生报告证明连接失败 | 暂停共享该 bridge/Profile 的 browser-backed OpenCLI；按 [连接诊断](opencli-windows.md#连接诊断) 核对及恢复，不将摘要 `not_ready` 或无效报告当成此类证据；不同已配置连接独立判断 |
| 站点 + 账号 | `AUTH_REQUIRED`、`SECURITY_BLOCK`、会话失效或账号挑战 | 暂停该站点／账号的自动抓取；按 [登录准备与恢复](opencli-windows.md#登录准备与恢复) 在原绑定环境交接用户处理，不靠换同登录态浏览器重试，不擅自换账号或读取 Cookie |
| site + action | 命令缺失、结构漂移、解析异常、动作不支持 | 其他站点和独立动作继续；仍影响目标的适配器缺陷进入下文修复，不直接转浏览器 |
| `empty` | 请求成功且确认没有匹配项 | 如实报告，必要时调整一次查询范围；不是故障 |
| `partial` | 未证实空结果、关键字段缺失、截断或证据只覆盖部分问题 | 保留已验证部分；只为缺口补充相关读取，不全局熔断 |

OpenCLI 的明确 Profile、原生 doctor 与等待预算见 [执行与升级边界](opencli-windows.md)。诊断成功不等于业务成功；CLI 超时或 `error.outcome: unknown` 都不能证明原动作没有执行。

## 有界恢复

1. 记录 provider、选定 Profile、动作、exit code、stdout、stderr 和已知错误码，不只保留 stdout。
2. 同一候选动作在适配器未改变时，普通失败最多追加一次有明确依据的重试；验证码、认证失效、账号风控和共享连接已失败时不盲重试。连接恢复后可在剩余预算内验证原目标动作；同一任务的较新证据替代旧状态，不能让已恢复前的探针永久禁用候选。为正文、评论、发布时间等不同证据缺口执行必要读取不算重复重试，取够即停。适配器改动后的验证按下一节单独计轮，不以普通重试额度耗尽提前退出修复。
3. 替换候选时明确绕开哪条失败依赖。优先可用专用 API／CLI；平台抓取转通用浏览器必须先满足下一节门槛，再按 [浏览器选路.md](浏览器选路.md) 选择环境，不把默认 ego-browser 当成所有故障的唯一恢复路径。
4. 暂停状态按上述作用域记录。认证要求或会话失效按 [登录准备与恢复](opencli-windows.md#登录准备与恢复) 提前说明并主动准备原绑定环境的人工入口；这不属于抓取重试或浏览器兜底。收到明确恢复信号后核对目标访问，再继续原 CLI 动作，仍有挑战则停止；适配修复轮次不重置。下一独立任务重新判断当前条件，仍有连接疑点时按 [连接诊断](opencli-windows.md#连接诊断) 探活。历史失败保留日期与版本，不能永久禁用候选。
5. 平台读取任务可按需运行只读诊断，不自动升级、重装或修改环境；需要环境修复时沿用用户已有授权，否则报告具体阻塞。

上述重试限制约束 Agent 重新派发业务动作；底层工具的有界连接恢复由其执行契约负责，不因此获得重复提交业务动作的授权。动作超时或结果未知时先确认旧动作结束，再决定是否换路。

例如，小红书 `note` 解析失败不阻止 X 搜索；选定 Profile 的 bridge 断连会影响使用它的两个平台；小红书 Cookie 失效不证明 X 账号失效。真实无匹配、缺少发布时间、登录失败和目标已删除也不能互相代替。

## 适配器修复与浏览器兜底

本节统一定义平台内容抓取的修复轮次和浏览器兜底条件。用户指定环境、专用官方／已连接来源和更适用的专用 CLI 仍按 [平台路由](platform-routing.md#发现与执行) 选择；不得用本节改写这些优先条件。

1. **先确认动作与缺口。** 从当前注册表和帮助发现适用 OpenCLI 动作，执行最小有效业务请求并验收。结构、选择器、页面路径、字段解析或媒体归属发生变化，且缺口仍影响目标时，进入适配修复。已有动作缺参数或缺字段时，先检查现有适配器是否可补齐，不以“没有参数”直接批准浏览器兜底。真实无匹配、目标确无媒体或已有足够内容时，直接交付，不制造修复。
2. **在原授权内直接修复。** 按 [OpenCLI 修复入口](OpenCLI融合.md#5套原始-skill-的加载边界) 读取当前 `opencli-autofix`，需要开发能力时补读 `opencli-adapter-author`。已有授权覆盖的低风险、可恢复的本地 adapter 修复直接执行；先核对当前实际版本、源码及已有 override，保留恢复依据，再用原生 eject／override 维护。不得直接修改全局 npm 包、固定上游快照或覆盖其他本地定制；安装、登录配置、共享进程重启及对外发布不由抓取任务隐式授权。
3. **最多完成3轮有效修复。** 每轮必须包含失败证据、据此提出的修复假设、对应脚本差异、原目标实际请求与内容验收，以及相关正常路径验证。后续轮次根据前轮结果调整假设或方法；可按证据检查页面控件、加载状态、数据响应或关联动作，不机械规定每轮技术。首个业务失败、doctor 探针、查看帮助／DOM、没有脚本改动的重跑，以及同一假设下反复调整等待时间都不另计有效修复轮次。改动后的验证不受上一节普通重试一次的额度限制，但仍有界并遵守停止条件。
4. **成功即停，预算不重置。** 任一轮满足原目标即停止修复，保留必要补丁／override 与回归证据，不为凑数继续。轮次按同一任务的 `site+action` 与尚缺证据累计，换查询词、换脚本文件、重新读取 Skill 或恢复会话不清零。不得换目标、减小覆盖要求或把 `ok:true` 当成内容完整来取得通过。
5. **三轮后才批准抓取兜底。** 3轮有效修复均未完成原目标时，记录每轮证据、差异与验证结果，明确剩余缺口；核对 ego-lite 能解决该缺口且不复用已失败的账号／进程等依赖后，才转入 [浏览器选路](浏览器选路.md)。只能补未完成部分，不重取已足够内容，不把兜底成功当成 adapter 已修复。未满3轮且没有新的修复依据、缺少必要权限或无法继续验证时，保留已取得结果并报告具体阻塞，不编造轮次，也不提前转浏览器抓取。
6. **先处理非适配器阻塞。** 明确连接失败、登录失效、验证码、账号风控、权限拒绝、用户接管和执行结果未知时，先按对应作用域恢复或停止；这些不计修复轮次，也不因累计3次错误而解锁兜底。登录与验证可按 [登录准备与恢复](opencli-windows.md#登录准备与恢复) 在原绑定环境交给用户处理；这不批准浏览器自动抓取。独立的已授权专用 API／CLI 可继续，不通过换同登录态浏览器绕过限制。恢复后继续原目标并沿用已有修复轮次；无适用工具或需超出授权才能建立适配能力时，如实报告前提，不能假称已修复3轮。
7. **按证据区分浏览器用途。** 用户明确指定浏览器，以及画面、布局和交互本身就是目标的任务，按浏览器路由直接执行，无需让 CLI 先失败；混合任务中的文字、评论和素材获取仍遵循平台规则，不借“需要看图”将全部抓取转浏览器。可用 OpenCLI Browser 观察页面、网络、解析中转或辅助修复，这仍属 OpenCLI 路线；取得临时直读结果时记录实际动作，不冒充站点 adapter 已修复。普通平台正文需要渲染、展开或时间筛选，本身不构成绕过修复门槛的视觉／交互任务。

修复记录至少保留目标与所需证据、工具版本及 Profile 代号、原失败、每轮假设／改动／原目标与正常路径结果、剩余缺口和换路依据。完整访问参数与真实内容只放任务获准的本地目录，公开回归使用合成样本。未成功的改动不得破坏既有正常动作；收尾时核对本轮差异并撤销已确认无效或破坏正常路径的本轮改动，保护原有定制。

## 哪些降级有效

| 候选路径 | 可绕开的依赖 | 仍可能共享的依赖 |
|---|---|---|
| 原站 HTTP／专用 CLI | 浏览器进程、扩展与 DOM 适配器 | 原站限制、本机网络、显式配置的账号 |
| OpenCLI → 同一 ego 的 ego-browser | 可绕开 OpenCLI adapter／bridge | ego 进程与该 Profile 登录态 |
| 本机 fetch → 第三方 reader | 本机 HTTP 实现及部分网络限制 | 原站限制、第三方配额与数据外发边界 |

ego-lite 不可用或能力不足时报告浏览器路径阻塞，不切换 Chrome、其他宿主浏览器或独立 DevTools；本地 Web UI 调试例外见 [浏览器选路](浏览器选路.md)。

上表只说明依赖差异，不构成换路批准；平台抓取仍须通过上一节兜底门槛。HTTP 403／429、网关错误或验证页只证明当前通道失败，不能据此声称内容不存在。切工具不能绕开用户授权、登录要求或账号风险限制。

## 统一结果语义

stderr 中仅过滤格式完整的独立 `LOOKUP_UPSTREAM_NOTICE` 通知行，再识别结构化错误。多个错误信封不选择其中一个充当唯一结果；任何信封明确表示执行结果未知时，归一化后仍保留未知状态。

`scripts/normalize-result.py` 从 stdin 读取已捕获的信封：

```json
{
  "provider": "opencli/douyin/search",
  "exit_code": 0,
  "stdout": {"ok": true, "data": []},
  "stderr": "",
  "url": null,
  "access_url": null,
  "evidence_type": "metadata",
  "empty_confirmed": false,
  "truncated": false,
  "missing_fields": []
}
```

只把工具实际捕获的值写入信封，不能用丢弃 exit code/stderr 的 stdout 管道冒充完整结果。helper 按需输出 `ok / empty / partial / error`，保留 items 或 text 与证据字段；它不是调度器、登录检测器或真实性证明。归一化脚本 exit 0 只说明信封处理完成，查询成败以返回 JSON 的 `status` 为准。

OpenCLI 的外层失败优先处理；成功信封解包 `data` 后仍须检查业务错误、未知结果、空值、截断和字段，不能因外层 `ok:true` 跳过内容验收。`ok:false` 或 `error.outcome: unknown` 不当内容。

`weixin/download`、`twitter/download`、`xiaohongshu/download` 另按实际下载行的 `status` 归一化：全失败为 `error`，混合或未知状态为 `partial`；公众号明确的验证页状态保留 `SECURITY_BLOCK` 与账号停止边界。保留原行供诊断。成功行仍只证明返回形态，必须另验正文与文件；其他动作的同名字段不按下载状态解释。

`stdout_format` 可选为 `json / text / auto`；已知 `lookup/fetch` 和 `lookup/subtitles` 默认按文本处理，其他 provider 默认自动判断。明确取得的自由文本可传 `text`，避免将方括号开头的正文误当 JSON。

- `url` 用于出处；`access_url` 保留后续访问必须的完整参数，两者不可盲目互换。
- 时间、作者或互动数缺失时保持未知；已知上游占位零不能当成真实零。
- `full_text / excerpt / metadata / comments / subtitles / asr / visual` 区分证据类型；只有标题、口播或字幕不能证明画面细节。
- 已确认无匹配可标 `empty`；未经证实的空数组标 `partial`，不推断全部通道故障。`lookup/find-url` 的 JSON 书签／历史集合会分别保留 `collection`，只采信该脚本 stderr 的确认空状态；exit 3 的有界预览仍为 `partial`。
- 同一结果可支持部分结论；只有缺失部分影响判断时才继续请求。
- helper 仅使用 Python 标准库；识别完整 JSON，以及上游提示之后由本地 runner 输出的最后一行严格 JSON 错误信封；另识别 OpenCLI 严格的 YAML `error / code` 子集，不依赖 PyYAML。其他格式由调用方保留原始 stderr，helper 仅给出 `UNKNOWN` 分类，不复制可能含敏感信息的原始消息；不靠文案猜测故障类别。

## 策略台账维护

`references/providers.json` 是必要合约和任务边界资料，不保存可执行命令模板；候选按数组顺序列出，实际筛选见 [任务选路.md](任务选路.md)，不自动执行或降级。`scripts/selftest.sh` 只读取 OpenCLI 必要合约，与各动作的实时结构化帮助比较；不证明返回内容、账号或所有平台可用。

只维护跨工具优先级、必要字段、授权／证据边界与失效作用域，不复制整个 OpenCLI 注册表。升级后检查安装版本、必要合约与受影响的最小真实场景；报告哪些未验证，不维护容易过期的固定成功率或单点统计。
