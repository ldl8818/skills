# YouTube 字幕与视频证据

用户要求了解指定视频时，始终围绕同一个 URL 获取证据。简介、字幕、ASR 转写和画面观察分别说明；只取得语言内容时，不声称核验过界面、图表或完整画面。B站先从当前工具注册表选择对应字幕动作，不套用 YouTube 命令。

## 选择字幕轨道

1. 已有完整字幕或可用的当前轨道信息时直接复用；否则用已安装的 yt-dlp 查询人工字幕、自动字幕及语言。先核对当前帮助；URL 和选项通过独立 argv 传入。

   ~~~bash
   yt-dlp --no-playlist --skip-download --list-subs "<目标URL>"
   ~~~

2. 优先选择能够保留原意的人工字幕；没有合适人工轨道时再用自动字幕。人工轨道标签不保证翻译准确；发现明显专名误译或语义冲突时，优先核对原语言轨道，无法核对的部分保留不确定性。用户要中文摘要不代表只能读取中文字幕，可以读取原语言后总结或翻译。没有请求语言不等于视频完全没有字幕。
3. 在本任务新建的临时目录保存所选轨道；按实际返回文件名读取，不假定一定生成 .en.vtt。以下是参数结构，临时目录与语言由当前任务确认：

   ~~~bash
   yt-dlp --no-playlist --skip-download --write-subs \
     --sub-langs "<已确认语言>" --sub-format vtt \
     --paths "<本任务临时目录>" -o "%(id)s.%(ext)s" "<目标URL>"
   ~~~

   选择自动字幕时将 --write-subs 换为 --write-auto-subs。只取所需轨道；读取字幕使用的临时文件与下载完整视频、长期归档分开处理。命令使用宿主执行器的有限总时限，网络重试也须有界。
4. 检查实际文件存在、非空、语言正确且有可用时间段。不能只凭退出码或某条 warning 判断成功。警告与输出矛盾时，以真实字幕内容和覆盖范围为依据，不关闭沙箱或反复请求来掩盖故障。

## 清洗与定位

从 lookup 根目录执行：

~~~bash
python3 scripts/clean-subtitles.py "<实际字幕文件.vtt>" --max-output-chars 40000
~~~

脚本只读本地 VTT/SRT，保留每个输出片段的开始时间，仅去除相邻滚动字幕的重叠或相同时间段的重复；不做全局句子去重。普通重复对白、后文再次出现的句子及字幕中的字面文本都应保留。

stdout 是带时间位置的文本，stderr 是单个 JSON 状态对象：

- 退出 0 / status=ok：已处理可用字幕，仍需检查是否覆盖用户问题。
- 退出 3 / status=partial：正文预算导致截断，或有无法解析的 cue。查看 truncated、malformed_cues，只补影响结论的缺口。
- 退出 1 / status=error：输入不可读或没有可用的带时间字幕，不当成已证明原视频没有字幕。

40,000 字符是默认输出预算，最多读取 5 MiB 输入。需要更完整上下文时定向提高预算或读取相应片段；不要把部分字幕写成全片结论。读完后只清理本任务创建且已不再需要的临时文件，保留用户原有文件。

## 同一视频的备用能力

- yt-dlp 失败或所需轨道不可用时，检查当前 OpenCLI 的 YouTube transcript 动作与参数；它可能输出分组文本，columns 为空不代表该动作无用。
- 仍无可用字幕且任务需要口述内容时，使用已经配置并处于任务授权范围内的音频转写能力。YouTube 链接使用已融合的 `python3 scripts/reach.py run youtube transcribe <url>`；通用本地文件／URL 转写按融合入口调用私有环境的 `agent_reach.transcribe.transcribe`。运行时、服务商与费用前提见 [融合入口](Agent-Reach融合.md#配置诊断与维护)；不在普通查询中自动安装、升级或新开通付费服务。
- 区分字幕与 ASR 的来源；转写可能有漏词和专名错误，依赖精确措辞时回到音频或其他原始材料核对。
- 需要核对视频画面时，先使用合适且已可用的视觉／视频能力；确需浏览器时按 [浏览器选路.md](浏览器选路.md) 选择，外部网页只用 ego-lite。采样时间、等待新帧与覆盖边界见 [媒体读取.md](媒体读取.md#视频时间点与采帧)；打开播放页本身不能证明已读取音轨或画面。
- 所有候选都缺少所需内容时，说明具体缺口。用户指定的视频不能用另一个视频替代；不存在字幕不是整个 OpenCLI 或网络通道故障。

版本相关命令以当前已安装帮助和注册表为准。方案参考 [Agent Reach 视频能力](https://github.com/Panniantong/Agent-Reach/blob/14c213405669414492bda0f8d52cc6531d062c45/agent_reach/skill/references/capabilities.md)，不把其经验当作长期固定的平台保证。

## 完整音频转写

适用于同一目标视频没有可用字幕、用户仍需要完整口述内容的任务，包括 Douyin 等平台。先确认平台详情或授权播放器提供的是目标正片音轨；标题、简介、音乐名称与烧录字幕截图不能代替完整转写。

1. 从当前已授权访问取得目标媒体，只保存本任务必需的临时音频。`play_url` 可能包含签名，不能写入公开日志或交给未经授权的第三方。`blob:`、分段流或只有背景音乐的资源不能直接当作完整口播音轨。

   独立媒体工具返回403，但原授权页面可播放时，先核对原动作与访问状态；明确的账号挑战或权限拒绝仍按 [失败边界](failure-domains.md) 停止。没有此类阻断时，可用原页面的正式请求接口有界读取已观察到的目标资源，不猜签名、不导出 Cookie。音视频分离时选目标音轨，再核对文件实际流与时长；响应 MIME 或 URL 名称不能独自证明音轨完整。页面读取成功只证明访问上下文有差异，未经对照不能断言具体是 Cookie、Referer 或签名失效。

2. 用已有 `ffprobe` 核对音轨、实际时长与播放器时长；需要格式转换时用已有 `ffmpeg`，不加入截取参数。对分段流须确认覆盖正片起止，不能只处理最先加载的一段。
3. 用已配置、符合任务授权的 ASR 处理完整音频。记录引擎、模型、语言和处理范围；需要分块时保留原始时间偏移与接缝覆盖。普通阅读不自动安装依赖或开通服务；用户已授权修复转写环境时，可在任务隔离环境准备本地引擎，不能据此安装全局依赖或启用付费 API。
4. 核对实际输出非空、时间段合理且无输入裁剪或输出截断。将开头、中间、结尾与音频或同时间点烧录字幕交叉核对，重点检查数字、单位、专名和同音术语。校正须有原始证据，保留未经校对的输出与修改依据；无法确定的词标明不确定，不凭语句通顺补写。无对白的开头或片尾允许没有字幕，不能以最后一条字幕早于片尾直接判断遗漏；连续静音、背景音乐或明显幻觉须如实标记。
5. 交付区分“整段音频已处理”与“每个词均已人工校对”。转写覆盖不全时列明已覆盖区间；采样画面只支持相应时刻的视觉结论。任务结束后按素材用途清理或保留，不把临时媒体与模型缓存当正式内容提交。

Apple Silicon 上的本地引擎可按需参考 [MLX Whisper 官方说明](https://github.com/ml-explore/mlx-examples/tree/main/whisper)，以已安装版本的帮助为准；lookup 不维护模型推理实现。
