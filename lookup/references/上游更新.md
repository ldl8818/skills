# 更新提醒与维护

选用相关依赖或用户要求更新时读取。普通查询默认提醒；用户决定更新时机后，Agent 连续完成来源核对、候选验证、切换、失败恢复与结果报告。按依赖开启托管后，同一授权范围内不重复确认。

## 命令与范围

| 请求／命令 | 范围 |
|---|---|
| “更新／升级 lookup”“更新 lookup 这个 Skill”、`lookup update` | lookup 本体及全部已安装的受管上游。 |
| “只更新 lookup 本体”、`lookup update --self-only` | 仅 lookup 本体。 |
| “只更新 lookup 上游”、`lookup upgrade` | 已安装的 OpenCLI、Agent Reach、ego-browser。 |
| `lookup upgrade opencli`／`agent-reach`／`ego-browser` | 仅指定依赖。 |
| `lookup check` | 只读检查本体及已安装上游；Ego 不调用升级器探测远端版本。 |

自然语言升级由 skill-manager 统一发起：`update ego-lite`／`ego-browser`／`opencli`／`agent-reach` 委派到本安装的指定依赖入口。表中 lookup CLI 保留为内部维护与用户显式终端入口；原生升级命令是维护器内部步骤，不能绕过定制保护、维护回执与发现入口检查。其他独立 CLI／应用的接入见 [更新对象与执行入口](../../skill-manager/references/升级与定制合并.md#更新对象与执行入口)，不扩展 lookup 的受管清单。未安装 skill-manager 的独立分发仍可直接使用本维护器，不能直接跳到底层安装器。

旧 `lookup update <dependency>` 保留为指定依赖的兼容入口，不扩大到本体。`lookup update --auto` 保留既有 OpenCLI 托管范围，不自动更新本体或扩大其他依赖的授权；新调用优先用 `lookup upgrade opencli --auto`。`--self-only` 不与依赖名、`--auto`、`--retry` 混用。

Skill Manager 的 `update lookup` 委派总更新；`--self-only` 与 `--upstream-only` 分别委派本体与上游更新。它按实际解析到的安装路径调用脚本，不通过 PATH 选择另一份 lookup。单项、批量和检查入口都识别 `source: local` 的 lookup；旧安装缺少维护接口时明确报告，Agent 按完整来源与定制合并流程补齐接口，不虚报更新或静默遗漏。未安装 Skill Manager 时，lookup 的原生维护入口仍可使用。

单项维护结果携带所选 `dependency`，包括未安装、无需更新、延后和失败；批量结果按项携带归属。`deferred` 表示尚未完成，单项或批量含该结果均返回非零退出码；托管观察期延后同样如此，退出码不授权提前安装。`pending`、`interrupted` 与 `outcome_unknown` 明确返回 `outcome_unknown: true`、`retry_safe: false`，先核对原操作结果，不凭失败退出码自动重试。

## 本体来源与接续

本体更新需要已有 Git 及官方源网络连接。

本地版本号较高不能代替完整源内容比较。官方源仍有新内容时继续三方对账，保留必要的本地版本与定制，不把“防降级”当作跳过新能力的理由。

本体从本项目官方 `https://github.com/ldl8818/skills.git` 的 `main` 通道获取完整 `lookup/`，上游软件继续沿用各自已选择的来源与稳定版策略。只切换 lookup 目录，不拉取、重置或推进其所属仓库的 HEAD，不更新其他 Skill；本地版本领先源头时保留，不自动降级。非官方 Git 来源保持原状，报告来源不符，不擅自换源。

先使用按真实安装路径隔离的旧源回执。Git 安装没有回执时，旧基线取本地历史与官方选定通道共同可达的提交，且从官方快照读取内容；不能把任意本地 HEAD 或已提交定制当作纯上游。复制安装没有可核旧基线时保留本地内容，生成待判断材料。当前与新源完整一致时可登记源基线；本地与旧源有差异而新源变化时，必须完成下文的定制判断。

使用 `lookup review lookup` 查看本体三方材料，修改 `merged/` 并按下文格式登记判断；经核实的缺失基线可用 `lookup review lookup --baseline <directory> --scope lookup --source <verified-https-url>` 补齐。完成后执行 `lookup review lookup --accept <decisions.json>`，再用 `lookup update --self-only` 接续。并发改动时先执行 `lookup review lookup --restart`。禁用状态独立保留，三方材料统一使用 `SKILL.md`，发布时还原为 `SKILL.md.disabled`，不把启停当作源码定制。

本体在隔离候选中检查身份、版本、Python 语法和维护接口，保留完整原目录及被忽略的本机运行文件。发布必须核对审核时的本地源码指纹，审核结束至发布之间发生改动同样拒绝切换；之后继续检查切换前后的完整目录漂移。候选和备份位于本体状态目录的 `self-exchange-*`；跨文件系统不能原子移动时保持原目录并报告失败。发布失败只在能确认实际内容时恢复；不同的并发内容保留并标记待核实，不覆盖。切换后由新版本的维护器执行上游升级；中断时先让接续进程完成自有回收，不遗留仍在安装的子进程。

总更新逐项报告本体与上游的结果。本体待语义判断时，可继续按当前可用封装维护上游；本体实际切换状态未知时暂停上游切换。部分完成、原生 pending 或未知结果均返回未完成状态。另一个会话先读回请求、`self-transaction.json` 和实际目录，不盲目重发；本体恢复材料属于有效备份，不按临时文件清理。

## 使用时检查

从 lookup 根目录执行；只传本轮使用的依赖。OpenCLI 与 Ego 的随包运行入口会自动发起检查，其他入口由 Agent 调用：

```bash
python3 scripts/upstream.py check opencli --background
python3 scripts/upstream.py check ego-browser --background
python3 scripts/upstream.py check agent-reach --background
python3 scripts/upstream.py notices opencli ego-browser agent-reach
```

- 每项依赖的成功检查缓存24小时，失败后至少1小时再试；状态在 `XDG_STATE_HOME/lookup/upstream`，未设置时使用 `~/.local/state/lookup/upstream`。后台检查是有界的一次性进程，不安装依赖、不启动浏览器、不查询业务站点、不调用模型。
- 已缓存的通知可在启动时转述；新检查未返回时先完成查询，在收尾或下次使用时读取通知，不等待检查。`notices` 原子领取未报告的通知，同一依赖和目标版本只报告一次；运行入口的 `LOOKUP_UPSTREAM_NOTICE` 也必须简短转述，不能把原始 JSON 当用户通知。`already_notified: true` 只用于接续延后的托管，不重复播报发现新版。
- 检查失败、版本无法识别或依赖未安装均不等于没有新版，不因此中断查询。未安装的工具和仅借鉴方法的 web-access 不发升级提醒。只跟正式发布通道，不把 main 的未发布提交列成新版。
- OpenCLI 从官方 npm 发布源检查；Agent Reach 从官方 GitHub 发布源检查。Ego 当前公开接口只有包含安装的 `upgrade`，没有已核实的只读新版查询接口；这里只检测本机版本变化，发现变化后重新读取 `ego-browser skill` 并核对本地封装，不虚称已检查远端最新版。

## 自然语言维护与托管

用户明确更新某项上游时，先核对本机已接入的依赖及最新稳定版，按下述同一流程执行；未安装工具不新增。未限定范围的“更新 lookup”仍包含本体，不能因先触发 Skill Manager 或请求中出现“Skill”而缩小范围。更新包含必要兼容适配和验证，用户无需自行研究安装命令。

命令、自然语言维护和已授权托管均执行下文的[定制核对与合并](#定制核对与合并)。收到 `manual_review` 时，当前 Agent 继续完成比较、判断和合并，再接续更新；仅输出脚本的待处理状态不能算维护完成。独立终端没有正在执行判断的 Agent 时，保留当前内容并返回非零状态，用户可将回执交给另一个 Agent 会话接续。

```bash
python3 scripts/upstream.py policy opencli notify
python3 scripts/upstream.py policy opencli auto
lookup update
lookup update --self-only
lookup upgrade
lookup upgrade opencli
lookup upgrade agent-reach
lookup upgrade ego-browser
lookup upgrade opencli --auto
python3 scripts/upstream.py rollback opencli
```

- 默认 `notify`。只有用户明确要求开启该依赖的托管后才设置 `auto`；实现更新功能不等于替用户开启托管。关闭托管立即恢复只提醒。
- OpenCLI 的托管只采用已支持的同主版本稳定版，至少发布24小时；版本号不是兼容证明，仍须通过实际合约检查。主版本、预发布和无法识别的发布只提醒。已失败的同一版本不自动重复安装；用户明确要求重试时可再次手动维护。
- `lookup upgrade` 依次处理已安装的 OpenCLI、Agent Reach 与 Ego，逐项报告结果；缺失项跳过，一项失败不隐去其他项的结果，批量退出码反映是否存在失败或待确认。指定名称时只处理对应依赖。终端入口尚未安装时，可运行 `python3 scripts/upstream.py update` 总更新，或用 `upgrade` 只更新上游。
- 收到 `action: maintain` 的通知时，先告知准备更新，完成当前查询并释放本任务资源，再运行 `lookup upgrade opencli --auto`。报告成功、延后、失败或已恢复的实际结果；已授权的常规安装、兼容适配和验证连续完成，不中途逐项确认。
- OpenCLI 在状态目录隔离安装候选，禁用 npm 生命周期脚本。候选在独立 HOME 读取随包指南并逐项核对 lookup 所需的公开命令、只读权限、参数与字段，防止原生帮助改写用户运行目录。存在包内补丁、adapter override 或插件时先完成定制核对；合并后携带相同 adapter／plugin 在隔离 HOME 重验，再切换并保存覆盖文件的恢复材料。
- 完整融合版还遍历 [全部公开命令](OpenCLI融合.md#更新与完整性门禁)，核对当前1,289条基线命令及站点动作的读写属性；缺项、属性变化或分页不完整时不切换。新增命令作为额外能力保留，按实际帮助继续判断用途和授权。
- 切换只改变 lookup 使用的版本指针，系统的 `opencli`、原安装包、Profile、扩展和登录数据保持原状态。`opencli-run.mjs` 持有共享使用锁；候选准备不阻断查询，其他调用仍在执行时延后切换。明确绕过 lookup 直接运行的 OpenCLI 不受该锁保护，不据此声称全机无占用。
- 维护前后都核对有效版本；切换后核对失败时恢复旧指针。后续真实任务暴露候选回归时，先保留原输出、恢复旧版，再修复并定向验证，不自动重派结果未知的业务动作。合约通过不等于所有平台实测通过。
- `lookup upgrade agent-reach` 识别当前可执行文件对应的 Python 环境。uv／pipx 使用原管理器升级，保留其来源、额外依赖与安装记录；普通 venv 使用该环境的 pip 安装官方最新稳定 tag。先备份确切环境与启动入口，更新后核对实际版本、命令、随包 Skill 入口与参考目录；安装失败、版本未达目标或随包资料缺失时恢复，并保存回执与恢复材料。固定版本来源不能到达目标时明确失败，不解除固定版本或改用 main 冒充稳定版。
- Agent Reach 的可编辑／本地源码、非官方来源及无法识别的系统 Python 安装保持原状，报告具体原因；不使用 sudo、`--break-system-packages` 或换安装器绕过。更新不运行 `install --system`，不额外更新其他平台工具或覆盖用户定制 Skill。融合版还须通过 [完整能力门禁](Agent-Reach融合.md#更新与完整性)；缺少当前16渠道、11类 CLI 流程或7类参考时恢复原环境。随包资料随包验证，平台 doctor 按实际任务另行执行，不把包验证当业务通过。
- `lookup upgrade ego-browser` 调用当前原生 `ego-browser upgrade`，执行前告知可能重启浏览器；原生界面要求确认或用户接管时不自动点击。完成后重新核对 CLI 版本与带结束标记的完整 `ego-browser skill`；版本改变或明确的“已是最新”回执才可分别报告更新完成或无需更新。没有完成证据时保存 pending／outcome_unknown，不强关窗口或手动替换浏览器包。
- 原生升级未确认时，再次调用先读回状态与版本；已完成则核验并销项，仍未知则不重发。用户确认原操作已完成或取消后，可运行 `lookup upgrade ego-browser --retry` 显式重试；超时不表示浏览器端更新已取消。Ego 恢复由原生更新器负责，lookup 不承诺自动回退浏览器安装。
- Agent Reach 与 Ego 的脚本入口支持手动维护，`policy ... auto` 仍明确拒绝。`lookup update --auto` 只处理已授权的 OpenCLI，不据此扩大其他依赖的托管授权。

融合版在 Agent Reach／Ego 原生维护返回成功、等待或失败后，于同一维护锁内执行 [客户端发现检查](Agent-Reach融合.md#客户端发现与恢复)，迁出安装器重新注册的已识别竞争入口，保留来源及恢复账本。入口归档不改变原生升级状态；`pending`、`outcome_unknown` 和 `failed` 继续按原状态报告。入口冲突单独记录 `discovery_pending`；已确认升级成功的结果另返回 `manual_review`，不能把运行程序已升级说成整个维护已完成。消除冲突后重跑相同命令只接续入口处理，不再次调用原生升级器；等待中的原操作后来完成时，重新核对版本与指南，再按原事务恢复。已确认成功后的运行版本与记录不同则保留结果待核实。未完成的定制合并仍先走下文流程。

### 已由外部完成的原生更新

先核对原操作结果、当前 CLI、随包指南及实际运行版本。存在上述 pending／outcome_unknown 回执时按原事务接续；没有回执时记录本轮核验和缺失的事前证据，不补造保护快照，也不为获取回执重发升级。

确认原生更新已完成后，读取本机现存独立 Skill、定制与原始指南，按下节核对差异；随后运行 `python3 scripts/entrypoints.py audit --lookup-root /absolute/lookup`。发现已识别竞争入口时，在当前布局授权内执行同脚本的 `apply` 并再次 `audit`。归档回执与原始指南必须可读，冲突或独有定制未处理时不能报告维护全部完成。此流程只补入口和兼容验收，不代表重新执行过完整升级事务。

## 定制核对与合并

通用判断与执行流程统一见 [skill-manager 的升级与定制合并](../../skill-manager/references/升级与定制合并.md)；完整源与路由字段验收沿用其现有工具。lookup 的脚本负责快照、变更清点、回执核验和更新事务，正在维护的宿主 Agent 负责语义判断；后台版本检查不调用模型。本节以下只维护 lookup 的具体来源、回执和命令接续方式。

### 脚本回执与接续

OpenCLI 从官方 npm 的确切版本和 SHA512 建立旧源快照，同时比较实际安装包与用户覆盖；adapter 按“旧内置实现＋本地覆盖”的有效内容比较。Agent Reach 先用安装 `RECORD` 检查包内补丁及新增／删除文件；需要合并时，旧稳定 tag 的源码必须匹配原始 `RECORD` 哈希，才可作为旧基线。来源无法恢复、定制 launcher 或非标准链接均保留当前安装，交由 Agent 定向处理。

原生更新前保存独立 Ego／Agent Reach Skill。每个独立 Skill 都核对来源与定制，安装器没有改写文件也不能跳过；Agent Reach 能证明本地与旧随包原版一致时，可直接采用新随包原版。其他情况保存安装后的完整内容，保留原本地内容并记为 `manual_review`；回执会分别说明运行程序和 Skill 的状态。Ego 的独立 Skill 旧／新完整源码无法从原生升级接口确定时，Agent 须从已核实的官方对应版本补齐，不能把安装后的未知文件认定为纯上游。完成合并后只接续 Skill 应用与核验，不重复调用原生升级器。运行程序仍在等待或结果未知时保留原生状态，Skill 合并不得将其提升为更新成功。签名浏览器或不透明二进制的定制不做猜测式补丁合并，保留受支持的原生维护边界。

查看待处理材料与登记判断：

```bash
lookup review opencli
lookup review opencli --accept <decisions.json>
lookup upgrade opencli
```

`review` 同样支持 `agent-reach` 与 `ego-browser`。待处理目录中的 `request.json` 列出目标版本、作用域、在线路径、完整文件指纹、本地差异及来源是否已知；每个编号目录有只读依据 `base/`、`local/`、`upstream/` 及可编辑的 `merged/`。原生安装后的 `observed-after-install/` 保留安装器输出及可能的并发改动，Agent 必须一起核对；其中内容不能直接当作原始上游。Agent 只改 `merged/`，完整保留新版内容，再合入需要的定制。不要改写依据快照、请求或已登记哈希来绕过检查。

本地内容在判断后发生变化时，先运行 `lookup review <dependency> --restart` 重新采集，再重新判断与验证。该命令保留旧材料、创建新的合并目录，不复用旧批准，也不通过修改依据哈希来忽略并发变更。升级等待、失败及结果未知时，恢复本地 Skill 前同样保存每份不同的实际内容及哈希；回执中的 `observations` 提供恢复入口。

判断文件格式如下；本体的 `target` 使用请求中的固定 commit，`scope` 为 `lookup`；依赖示例如下。每个有本地差异的文件都要列出，文件内的多项行为在理由和验证中分别说明。所有相对新上游的最终文件差异，包括跨文件适配，也要在 `adaptations` 中说明：

```json
{
  "target": "2.0.3",
  "decisions": [
    {
      "scope": "package",
      "path": "clis/example/read.js",
      "disposition": "preserved",
      "reason": "New upstream still lacks the required empty-value behavior.",
      "evidence": "Compared old, local and new read implementations and their callers.",
      "validation": "The regression fixture retains null values; the normal fixture also passes."
    }
  ],
  "adaptations": [
    {
      "scope": "package",
      "path": "clis/example/read.js",
      "reason": "Preserve empty values while keeping the new pagination implementation."
    }
  ]
}
```

`disposition` 使用 `absorbed` 或 `preserved`；前者要求对应合并文件与新上游一致，adapter 不再需要覆盖时移除该覆盖文件。理由、依据与验证必须来自本轮检查，不可复制示例冒充实测。`--accept` 校验差异覆盖、目标与完整哈希；改动有 frontmatter 的上游 `SKILL.md` 时复用已安装或同仓库的 skill-manager 路由字段检查，保留完整上游原文，检查器缺失时保留待处理状态。它不会替 Agent 证明语义或测试是否真实。

仅当回执缺少原始基线时，可在核实官方原版本的完整源码后补入：

```bash
lookup review ego-browser --baseline <original-source-directory> \
  --scope skill-0 --source <verified-original-upstream-https-url>
lookup review ego-browser --upstream <new-source-directory> \
  --scope skill-0 --source <verified-new-upstream-https-url>
```

补入旧源使用 `--baseline`，缺少完整新源时使用 `--upstream`；两者分别记录来源与内容指纹。命令不负责确认来源可信或与对应版本相符，Agent 须先完成来源与完整性核对，不得直接把本地定制标为原上游。随后重新比较并登记判断，再运行对应 `lookup upgrade <dependency>`。接续时再次检查本地、目标及合并结果；任一内容漂移均拒绝套用旧判断。回执及恢复材料留在本机状态目录，不进入公开仓库。

## 验收与恢复

维护入口保留候选、验证和切换回执，供另一个会话继续核对；中断后先查实际指针和回执，不盲目重复安装或回滚。已安装成功的旧版是恢复材料，不作为临时文件清理。

上游文件与目录互换时，先核对目标位置是否含本机运行文件；有冲突则保留原对象并报告。OpenCLI 回滚同时恢复有效指针与配套覆盖文件；失败时恢复回滚前状态，二次恢复失败则保留 `ROLLBACK_RECOVERY_FAILED` 指向的恢复目录，核对其中材料与当前状态后再处理。

`lookup update` 的通过范围是版本、随包执行指南与已登记命令合约。Agent 还需按受影响场景运行相称回归；需要登录或浏览器的真实验证在已授权环境执行，缺环境时明确报告。下载失败、安装超时、合约变化、并发占用、状态损坏及回退失败均保留具体状态，不降级检查或宣布更新完成。

使用 `python3 -m unittest discover -s tests -p 'test_*.py'` 验证更新、定制合并及现有运行入口；按影响补充真实环境核验。干净 HOME 验收只证明该环境实际执行的步骤；不替代用户其他机器或所有平台验收。
